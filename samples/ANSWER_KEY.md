# Sample corpus — answer key

Generated by `Workers/scripts/generate_samples.py`. The standards and the designs
were written against each other deliberately, so most clauses have a knowable
correct verdict. That is what makes this an eval set rather than just test data:
without it you can only tell that an assessment *ran*, not that it was *right*.

```
samples/
  standards/   ← upload as "Reference standard"
    Data_Standards.pdf                     8pp · 13 clauses · 8 tables
    Security_Standards.pdf                 7pp · 12 clauses · 5 tables
    Solution_Architecture_Standards.pdf    8pp · 11 clauses · 4 tables · 1 diagram
  designs/     ← upload as "Design to assess"
    Customer_Portal_Modernisation_SAD.pdf  6pp — broadly compliant
    Field_Telemetry_Ingestion_SAD.pdf      5pp — several hard contradictions
```

**Setting**: Northwind Energy, a utility. The standards are its own library; the
designs are two submissions awaiting Architecture Review Board approval.

## Parser cases embedded on purpose

| Where | Case | What should happen |
|---|---|---|
| Data §8.1 | Retention table, Tier 4 leaves **RPO and Archive-After blank** | Cells stay `null`; Tier 4 must **not** inherit Tier 3's "90 days" |
| Security §2.2 | Password policy table **inside** the clause, not beside it | Table binds to the clause; "minimum 12 characters" is retrievable |
| Security §6.2 | Incident severity table **spans a page break** | Rejoined into one table, header not duplicated |
| Architecture §1.3 | Context diagram **rasterised — no text layer** | Extracted as a figure and described by the model |
| Data §9 | Records Management: heading, one sentence, **no content** | Raised as a `section_empty` issue, not silently dropped |
| All five | Running header + footer on every page | Stripped; `Internal Use` captured as the document's classification |
| All five | Dotted-leader table of contents | Parsed as ground truth; body reconciles at **100%** |

Verified: all five parse with ToC coverage 100%, zero missing and zero
unexpected sections.

## Field Telemetry Ingestion — expected verdicts

The harder document. Four direct contradictions, each argued for in the text —
which is the realistic case, since designs rarely breach a standard by accident.

### Must get these right

| Clause | Expected | Why |
|---|---|---|
| Data §3.2 Single source of truth | **contradicts** | §2.3 connects directly to the billing system's Oracle database; the standard prohibits it explicitly |
| Data §6.3 Encryption | **contradicts** | §2.2 transmits over plain MQTT, arguing the private APN is sufficient |
| Security §5.1 Cryptographic standards | **contradicts** | Same passage; the standard forbids unencrypted transport "including private networks" |
| Data §7.2 Resilience and idempotency | **contradicts** | §4 discards failed messages; the standard requires a dead-letter queue |
| Architecture §5.1 Event-driven integration | **contradicts** | §3.1 has no schema registry and no version field, and argues versioning is unnecessary |

| Architecture §3.3 Statelessness | **covered** | §2.1 workers hold no state, scale horizontally, safely terminable |

## How to use it

1. Upload the three standards as **Reference standard**, wait for `ready`.
2. Upload one design as **Design to assess**, wait for `ready`.
3. Run the assessment and compare against the tables above.

**Scoring that means something.** The 16 "must get these right" rows are the
real measure. Two failure modes matter far more than the rest:

- a **contradiction reported as covered** — a gap shipped to production
- a confident **absent on something the design does address** — someone sent to
  fix what already exists

The `partial` and `needs_review` rows are softer; reasonable reviewers disagree
about them, and a verdict one step away from expected is not a failure. What
should never happen is a confident verdict in the *opposite* direction from the
evidence.

A high `needs_review` count is not a bad result. It means the guards in
`Workers/aidp/stages/analyse.py` are demoting verdicts the evidence did not
support, which is the behaviour worth having.
